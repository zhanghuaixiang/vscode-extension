# VSCode 单文件代码结构导航面板设计方案

> 
> 文档：vscode-code-nav-panel.md

## 需求一句话

在 VSCode 编辑窗口右侧出现一个「代码理解面板」，针对当前打开的单个 `.vue` 或 `.js` 文件，先给出有源码依据的文件导读和关键阅读路径，再展示可折叠结构树、语义分组与点击跳转，帮助开发人员快速理解陌生代码，而不只是找到代码的位置。

范围决定：当前支持单个 `.vue` 或 `.js` 文件，不做跨文件依赖图 / 全库报告；i18n 相关优化本期不做。VSCode 版本 ≥ 1.100。
产物定位：通用单文件代码理解插件 + 内置预设（可在 Vue 或 JavaScript 项目使用，ics 是首个适配场景，见「产品定位与通用性」）。
性质：本阶段仅出方案，不落地代码。

## 〇、产品定位与通用性

定位：一款通用的单文件结构导航插件，首期支持 Vue 2/3 的 `.vue` 文件和 JavaScript `.js` 文件；本仓库（ics）只是它的首个适配场景，而非绑定场景。

表格

| 层 | 是否通用 | 说明 |
| --- | --- | --- |
| 分析内核 | ✅ 通用 | `.vue` 使用 `@vue/compiler-sfc` 提取区块，`.js` 直接使用 `@babel/parser` 解析 AST；共用节点、分组与风险输出协议，与业务项目零耦合 |
| VSCode 壳（面板） | ✅ 基本通用 | 对 `.vue` / `.js` 文件开箱提供“结构树 + 点击跳转”，按文件类型展示适用的区块 |
| 语义分组 / 风险阈值 | ⚠️ 可外置 | 做成内置预设 + 可配置规则：无配置时用通用中性规则即可；每个项目可带自己的分组 / 阈值配置增强 |

落地形态（已定）：通用插件 + 内置预设

- 插件完全中性、可上 VSCode 市场；
- 内置「通用」「ICS (inspur)」等分组预设，凭一个配置项切换；
- ics 专属规则不与内核耦合，作为配置 / 预设承载，不影响插件通用可用性。

通用性带来的收益：

- 对外：可发布到市场，供其他 Vue / JavaScript 项目及团队复用；也天然契合“把结构化 JSON 喂给 AI”的延伸。
- 对内：ics 只需一个配置项即贴合本仓库的分组，零成本适配。

> 
> 对目录组织的影响：内核保持零项目依赖；项目专属分组 / 阈值作为配置样例放在插件附带示例配置中，不作为运行必需。

## 一、产品形态结论

做 VSCode 扩展，核心是一个右侧的 Webview 代码理解面板：导读与阅读路径优先，结构树负责定位，风险提示用于辅助 review。

选它的理由：

表格

| 形态 | 是否匹配 | 原因 |
| --- | --- | --- |
| VSCode Webview 右侧面板 | ✅ | 可承载导读、阅读路径、折叠树、风险提示与点击跳转；可利用 `webviewViewProvider` 原生机制 |
| 原生 Outline / Breadcrumb | ❌ | 只能平铺语法符号（methods 整块一个节点、tag 顶层），无法语义分组、无法 show 复杂度 / 风险标记、无法定位到具体方法体内部 |
| CLI + HTML 报告 | ⚠️ 补充 | 不做主形态；作为「右键导出 HTML」的附带能力，便于贴近 review/PR，或喂给 AI |
| 编辑器无关独立工具 | ❌ | 与 “人在 VSCode 里看” 的诉求不符 |

架构上仍坚持「编辑器无关的分析内核 + VSCode 壳」两层分离，原因：

- 内核用纯 Node + AST 解析，严肃、准确，与 VSCode 进程解耦；
- 内核产出的标准 JSON 以文件类型区分可用结构，未来可被「CLI (CI)」「HTML 报告」「喂给 AI」等新消费端复用，不绑定编辑器；
- 关键：新依赖（如 `@vue/compiler-sfc`、`@babel/parser`）全部装在内核自身，不污染主项目依赖，也不依赖主项目已安装的包。

## 二、以理解为目标的阅读体验

面板先回答“这个文件大致做什么、从哪里进入、关键数据如何变化”，再提供完整结构；不要把语法符号列表或风险数量当作理解成果。

### 2.1 文件导读（首屏）

- 展示可从本文件确认的内容：Vue 组件名 / JS 文件导出、入口（如模板事件处理函数、生命周期、对外导出）、关键状态声明与赋值、显式调用（如请求或工具函数），每项附原文件行号与跳转入口。
- 第一版导读可用固定模板归纳组件名、导出和入口等源码事实，不依赖 LLM。“文件职责 / 业务用途”不能仅凭命名猜测后写成事实；后续若基于代码证据生成简短描述，需标为“推测”并附依据。没有足够证据时展示“暂无法确定”，不编造结论。
- 大文件默认只列少量关键入口和路径，其余结构按需展开；保留“查看完整结构树”入口。

### 2.2 文件内关键路径

- `.vue`：优先串起本文件可识别的模板事件 → 对应处理函数 → 本文件内调用 / 状态写入；`.js`：优先串起导出 / 入口函数 → 本文件内调用 → 返回值或可识别的副作用。
- 每一步都可跳到源码，并标注关系类型及依据（事件绑定、静态调用、赋值等）；遇到动态调用、框架注入或无法静态解析的目标时明确显示“无法确认”，不画成确定的执行链。
- 仅分析当前文件内的连接；外部调用可显示名称、位置与“跳出本文件”的提示，不自动递归分析依赖，也不宣称已追踪完整运行时流程。

### 2.3 按任务阅读

| 入口 | 首屏重点 | 交付顺序 |
| --- | --- | --- |
| 了解这个文件 | 文件导读、主要入口与关键路径 | 第一版默认模式 |
| 准备修改这个函数 | 当前函数及本文件内调用、状态写入和相关模板事件 | 第一版后增强 |
| Review 本次改动 | 当前文件改动触及的节点及相关路径，风险提示作为辅助 | 后续增强；无可用 diff 时提示并回退到文件导读 |

模式是同一份单文件分析结果的不同筛选视图，不因切换模式扫描整个仓库。是否提高理解效率，需以实际阅读任务验证（见第六节）。

## 三、内核输出 JSON Schema（v1）

以 `vm/popup/copyvm.vue` 这类巨型文件为例，面板的根对象：

```
{
  "version": 1,
  "file": "src/components/vm/popup/copyvm.vue",
  "fileType": "vue", // vue|js
  "meta": {
    "totalLines": 173000, // 便于巨型文件识别与"只看重点"
    "componentName": "CopyVm", // name 字段
    "sizeRank": "huge" // small|medium|large|huge
  },
  "template": {
    "rootEl": "div.copyvm",
    "tree": [ /* 见 3.1 */ ]
  },
  "script": {
    "name": "CopyVm",
    "props": [ "..." ],
    "computed": [ ... ],
    "data": [ ... ],
    "watch": [ ... ],
    "hooks": [ ... ],
    "groups": [ /* 见 3.2: methods 语义分组 */ ]
  },
  "imports": [ /* 本文件 import / require / 可识别的懒加载引用（仅名称+行号，非依赖图） */ ],
  "guide": {
    "summary": { "text": "可确认的结构摘要", "confidence": "fact", "evidence": [210] },
    "entries": [ /* 入口节点：类型、名称、原文件行号 */ ],
    "state": [ /* 可定位的状态声明 / 写入 */ ]
  },
  "paths": [ /* 文件内连接：起点、终点、关系类型、证据行号及是否确定 */ ],
  "risks": [ /* 后续增强，可选；见 3.3 */ ]
}
```

> 
> 「不做依赖图」的落点：`imports` 只列出本文件引用了哪些本地组件 / 工具并带行号，不递归展开它们、不统计被谁引用。
>
> `.js` 文件使用相同的根协议，`fileType` 为 `js`，`template` 为 `null`，`meta.componentName` 为 `null`；`script` 展示顶层函数、类及其方法、导出、重要变量 / 对象方法与 `groups`。各节点保留原文件行号以供跳转；Vue 专属字段（props / watch / hooks 等）仅在可识别 Vue 组件选项时提供，不要求普通 JS 文件具备。
>
> `guide` / `paths` 优先来自可定位的确定性分析；`confidence` 区分源码事实与后续可能加入的推测，所有推测需带证据且可关闭。路径仅含当前文件可确认的边，不把静态关系等同于实际运行轨迹。`risks` 为后续可选字段，第一版不依赖风险扫描。

### 3.1 Vue template 组件嵌套树（template-tree.js）

把 `<template>` 解析成一层层组件嵌套树，每个节点带：

```
{
  "tag": "el-form",        // 标签名
  "isComponent": false,    // 是否自定义组件（首字母大写/含-）→ 高亮
  "lineStart": 120, "lineEnd": 320, // 源码行区间 → 点击跳转
  "attrs": ["label-width", "model"],
  "listeners": ["submit"], // @xxx / v-on:xxx 事件
  "children": [ ... ]      // 递归
}
```

- 只对深一层有意义：默认展示到「自定义组件」这一层即可，Element 标签可折叠，避免树过深；
- 每个自定义组件节点可一键「只显示该子树」—— 看大文件的某个子块时聚焦。
- 普通 `.js` 文件没有 template，面板不展示空的 template 树。

### 3.2 JavaScript 结构与语义分组（script-map.js）

`.vue` 的 `<script>` 与独立 `.js` 共用 JavaScript AST 分析：识别 ES module / CommonJS 的导入导出、顶层函数声明、函数表达式、箭头函数、类及其方法、对象方法；保留名称、类型和源码行区间。`.vue` 额外识别 Vue 组件选项（props / computed / data / watch / hooks / methods）；若结构并非 Options API，也要展示可识别的普通函数与声明，不强行归入 methods。

对可识别的函数 / 方法使用命名规则 + 关键词启发式聚成语义分组（hostBtns.vue 里就是一堆 openXxx / xxxDisableTips，天然可分）：

```
"groups": [
  {
    "label": "弹窗打开(Open)", // 组名
    "rule": "name startsWith open|add|edit|create",
    "methods": [
      { "name": "openCreateVm", "kind": "method", "line": 210, "bodyLines": 12, "risky": false }
    ]
  },
  { "label": "状态判定/is|can|check", "methods": [ ... ] },
  { "label": "生命周期/hooks", "methods": [ ... ] },
  { "label": "其它/uncategorized", "methods": [ ... ] } // 兜底组
]
```

分组节点 `kind` 可为 function / method / classMethod 等；对无法可靠识别名称的声明，用类型和行号作为导航标签，并归入兜底组。所有行号以原文件为准，不使用截取后的 script 偏移行号。

分组规则分为基础层与后续增强：

1. 第一层：确定性规则（前缀 / 关键词）—— 离线、快、可复现，保证工具自测稳定；
2. 第二层（后续可选）：把组内方法名批量喂给一个 LLM 做更智能的语义归类，产出“增强分组”，失败则回落到规则分组；第一版无需依赖模型或上传源码。

### 3.3 风险标记（risk-scan.js）

后续在树 / 函数 / 方法节点上打标，辅助 review；风险扫描不是代码理解首屏的主体：

```
"risks": [
  { "type": "longMethod", "line": 860, "name": "saveVm", "bodyLines": 480, "level": "warn" },
  { "type": "v-html",     "line": 915, "level": "error" },
  { "type": "console",    "line": 220, "level": "warn" },
  { "type": "TODO|FIXME", "line": 512, "level": "info" }
]
```

规则：函数 / 方法体行数阈值（如 >200 警告、>500 高危）、console、TODO/FIXME、`catch(){}` 空块等；`v-html` 仅适用于 `.vue` 模板。风险只标注可定位的代码现象，不等同于已确认的漏洞。

## 四、VSCode 面板交互设计（右侧悬浮目录）

### 4.1 如何出现

- 激活事件覆盖 Vue 与 JavaScript 文件；扩展激活后注册一次 Webview View Provider，后续只切换分析目标，不重复注册视图；
- 面板目标是编辑区右侧的导航视图；VSCode 视图可由用户移动到右侧辅助侧边栏，具体默认位置需按扩展 API 可用性验证，不假设插件可强制指定右侧；
- 跟随当前活动编辑器：`window.onDidChangeActiveTextEditor` → 切换到 `.vue` / `.js` 时自动更新一次导航（切回同一文件也触发）；其他文件显示“不支持该文件类型”，不沿用上个文件的结果。

### 4.2 面板内容（Tab 结构）

第一版：`[文件导读与阅读路径] [完整结构]`；后续可增加 `[风险] [源码视图]`。

- 文件导读与阅读路径：默认首屏展示摘要、可点击的关键入口与文件内连接；可按“了解文件 / 准备修改函数 / Review 改动”切换重点（模式分期交付）。
- 完整结构 Tab：`.vue` 展示 template 树 + script 分组树；`.js` 展示函数 / 类 / 导出 / 分组树，不显示无意义的 template 区块；各节点可折叠；
- 风险 Tab（后续增强）：按 level 排序，点击跳转，不用风险数量代替理解进度；
- 源码视图 Tab（可选增强）：把大文件按结构切成可折叠区块，面板内即可浏览缩略内容，减少来回跳编辑器 —— 提升 “看目录就够” 的比例。

### 4.3 点击跳转

前端节点点击 → `postMessage({ type: "reveal", file, line })`；扩展侧校验文件和行号，确保切换文件或分析尚未结束时不会跳到错误位置。

### 4.4 状态与性能（重点：巨型文件）

刷新策略（已定）：文件激活 / 切换回来时自动更新一次；不实时跟踪编辑或保存，另提供手动刷新。

- 手动刷新按钮：面板顶部固定一个刷新按钮（+ 编辑器右键菜单“刷新代码导航”命令）；点击强制重新分析当前文件。
- 触发时机：首次打开、切换到或切换回受支持文件时，自动发起一次结果更新；没有自动 save/watch 分析，不持续占用 CPU。若内容未变化，可命中缓存而无需重复解析。
- 分析基于 VSCode 当前 TextDocument 内容，包含未保存的编辑。缓存以文件 URI + 内容版本 / 指纹校验有效性（不能只依赖磁盘 mtime）；切回文件时内容变了就重算，未变直接复用。手动刷新绕过缓存。
- 切换时先显示“分析中”或当前文件缓存结果，完成后更新；对于异步任务按目标文件 / 请求序号丢弃过时结果，避免旧文件分析结果覆盖新文件。
- 巨型文件的解析不得阻塞扩展宿主；必要时通过 worker_threads 分析当前文档快照，性能目标以实测数据为准；
- Webview 渲染用懒加载折叠（只渲染展开节点 + 虚拟滚动），`network.vue` 这类深树也不卡；
- 面板给出「分析耗时」「总行数」「可确认的入口 / 路径数」一行摘要；风险模块上线后再补充风险数。

## 五、不做什么（明确边界）

- 不做跨文件依赖图：`imports` 仅平铺列出本文件引用的本地组件 / 工具（带行号），不递归、不统计被引用方。
- 不推断完整运行时调用链：只展示当前文件可静态确认的关系，并区分“确定”和“推测 / 无法确认”。
- 不做 i18n 校验补齐：本期不触碰语言包。
- 不做全库报告 / 代码体检（那是既往前述另一个方向，本期聚焦单文件导航）。
- 不做实时刷新 / watch：只读分析，仅在打开 / 切换（含切回）文件 + 手动刷新时触发；不监听保存、不 watch 磁盘（无持续解析开销）。
- 不改变业务代码：纯只读分析，无写文件、无侵入构建。

## 六、里程碑与验收

表格

| 阶段 | 内容 | 验收标准 |
| --- | --- | --- |
| M1 内核 + CLI | Vue SFC / JS AST 解析、结构归一化、文件入口与文件内静态关系提取 + cli.js | `.vue` 的模板事件可定位处理函数，`.js` 的导出可定位本文件函数；每条连接有类型、证据行号，未知目标不伪装为确定关系 |
| M2 理解面板 | VSCode 壳 + 文件导读 / 阅读路径首屏 + 完整结构树 + 自动更新 / 手动刷新 | 打开 `.vue` / `.js` 先看到可跳转的关键入口与路径，再展开结构；切回文件自动更新，未保存内容变更可见 |
| M3 阅读体验 | “准备修改函数”模式、懒加载渲染、缓存、异常兜底 | 打开巨型文件不卡、跳转准；异步结果不串台；用户能沿路径回答入口、状态变化与本文件内的调用关系 |
| M4 后续增强 | “Review 本次改动”模式、风险 Tab、可选 LLM 分组 / HTML 导出 | 缺少 diff 或模型不可用时明确提示并回退，不阻碍基础阅读能力 |

理解效果验收：选取若干真实陌生文件和未接触过这些文件的开发者，安排相同类型的任务（如“这个操作由哪里触发、最终写入了什么状态”）。记录不使用 / 使用插件时的定位耗时与答案正确率；同时核对导读及路径是否有错误断言。具体改进目标在试用基线确定后设定，不能只以节点数量、分析速度或点击次数宣称提升了理解效率。

## 七、风险与对策

表格

| 风险 | 对策 |
| --- | --- |
| 巨型 `.vue` / `.js` 解析与渲染卡顿 | 必要时内核 worker 化 + Webview 懒加载渲染 + 结果缓存 |
| `@vue/compiler-sfc` / `@babel/parser` 解析特殊写法失败 | 解析失败时降级为“可识别的分区 + 原始行列表”，同时展示错误，不白屏 |
| 文件切换时异步分析结果串台 / 缓存过期 | 以文档快照做缓存有效性判断，按请求序号丢弃过期结果 |
| 文件职责推断或静态路径被误当成真实执行链 | 只输出带源码证据的事实，推测单独标记；动态连接不确定时明确留白 |
| 语义分组不准（启发式规则有限） | 规则组保底 + 可选 LLM 增强层，LLM 不可用自动回落到规则组 |
| 扩展依赖与主项目冲突 | 工具 / 扩展独立 `node_modules`，不共享主项目依赖 |

## 八、一句话总结
