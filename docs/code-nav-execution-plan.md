# 单文件代码理解面板执行计划

依据：[需求方案](vscode-code-nav-panel.md)。本计划只安排开发工作，不在本阶段实施代码。目标是在现有 rapid-tools 扩展中增加独立能力，让开发者打开陌生 `.vue` / `.js` 文件后，先看到有证据的导读和文件内阅读路径，再按需展开结构树。

## 交付边界

- 第一版包含：Vue 2/3 SFC 与普通 `.js` 文件的结构解析、可确认的文件内连接、文件导读、结构树、源码跳转、切换回来自动更新、手动刷新和基础性能保障。
- 第一版不依赖 LLM；不做跨文件依赖图、完整运行时调用链、风险扫描、HTML 导出、全库索引或 i18n 改造。
- 分析当前编辑器的 `TextDocument` 快照，包括未保存内容；所有描述必须能定位证据。动态调用或无法解析的关系标记为未知。
- 开发完成的判定不止是“能展示树”，还要让试用者更快且正确地回答关于陌生代码的问题。

## 阶段与交付

| 阶段 | 主要任务 | 交付物 / 通过条件 | 参考工作量* |
| --- | --- | --- | --- |
| M0 技术验证 | 用最小扩展试验 Vue / JS 解析器打包、Webview 视图位置、worker 打包和大文件读取；确定 Webview 资源安全策略及 CLI 与扩展共用内核的方式 | 技术决策记录；`npm run compile` / VSIX 安装后均能运行最小解析和视图；确认右侧位置是否需要用户移动到辅助侧边栏 | 1-2 天 |
| M1 分析内核 | 定义版本化 JSON 与节点 / 证据 / 关系类型；解析 Vue template、Options API / script setup 中可识别结构及 JS 的 ESM / CommonJS、函数和类；抽取静态文件内边；提供 CLI | 同一份文档快照在 CLI 与扩展中产出一致结果；源码行号准确；无法确认的边不标成执行事实；解析失败时提供部分结构和错误说明 | 4-7 天 |
| M2 理解面板 | 注册独立视图和命令；实现首屏导读、关键路径、完整结构树、节点跳转；支持活动文件切换、切回更新、手动强制刷新及不支持文件的空状态 | `.vue` / `.js` 均可从入口沿文件内路径跳到源码；未保存修改在切回文件后可见；切换文件时不会展示上一个文件的路径 | 4-6 天 |
| M3 稳定性与试用 | 加入缓存、异步任务过期丢弃、懒渲染和必要的后台解析；补齐异常处理；实现“准备修改这个函数”聚焦模式；开展真实阅读任务试用 | 巨型文件不阻塞编辑器，跳转与证据仍正确；试用结果有耗时、正确率和错误断言记录；根据反馈修正入口排序和路径呈现 | 3-5 天 |
| M4 后续增强 | 评估“Review 本次改动”、风险提示、可选 LLM 分组与 HTML 导出 | 单独评审是否进入下一迭代；任何可选服务不可阻断离线基础功能 | 另行估算 |

\* 粗估为一位熟悉 VS Code 扩展的开发者的纯开发时间，不含等待真实项目样本、试用反馈与发布审批；M0 的结果可能调整后续估算。

## 建议实施顺序

1. **先确定协议和样本**：选取小型 Vue Options API、Vue `script setup`、普通 JS ESM / CommonJS、复杂大文件各至少一份；为每份样本人工标注入口、可确认关系和行号。先约定 `fileType`、节点 ID、源码位置、证据、关系状态及可选字段的含义。
2. **抽离编辑器无关的内核**：建立 `analyze(source, fileName)` 等纯函数接口，以同一输入服务 CLI 和扩展；内核可独立组织，但最终依赖必须随扩展正确打包，不要求用户项目安装解析器。先做结构与位置，再做事件绑定、静态调用和状态写入。
3. **做好证据约束**：Vue 的 `@click="save"` 能定位时才连到 `save`；JS 的直接本地函数调用才能连确定边。动态属性、别名、注入、跨文件调用只展示可观察信息或“无法确认”，不生成猜测的链路。
4. **接入现有扩展**：从 `src/extension.ts` 注册新视图和命令，保持与转换、i18n 功能隔离；Webview 仅通过受控消息请求跳转，扩展侧核验目标 URI、节点与行号。视图默认位置以 M0 实测为准，不承诺插件能强制固定在右侧。
5. **最后做性能与体验收敛**：按当前文档快照建立缓存，手动刷新绕过缓存；切换目标时取消或忽略旧请求的结果。大文件先限制首屏节点数，懒渲染树；若解析占用扩展宿主，再用 worker 隔离。

## 测试与验收

- **内核单测**：Vue 2 Options API、Vue 3 `script setup`、无 template、JS ESM / CommonJS、箭头函数 / 类、别名与动态调用、语法错误；检查节点、关系、证据、原文件行号及未知状态。
- **扩展集成测试**：打开 A → B → A、切换途中分析仍在运行、未保存修改后切回、手动刷新、不支持文件、空文件、解析失败；验证面板内容与跳转位置，不影响现有命令。
- **性能基线**：记录小 / 中 / 大文件的解析耗时、内存和首次可交互时间；以真实大文件样本验证不阻塞扩展宿主。先测基线，再设定可复现的阈值，不能预设 173K 行一定在固定毫秒内完成。
- **理解效果**：邀请未读过样本文件的开发者，分别在有 / 无插件情况下完成“入口在哪、更新了哪个状态、本文件内还调用了什么”等任务；记录耗时、答案正确率与错误断言。若速度提高但正确率下降，不能算通过。

## 需要在 M0 锁定的选择

- VS Code 当前 API 对默认右侧视图位置的实际支持情况；若只能由用户移动，需给出首次使用指引。
- Vue `<script lang="ts">`、JSX 等超出首期 `.js` 范围的语法是解析为部分结构还是提示暂不支持；必须有明确降级，不白屏。
- CLI、worker 与 Webview 静态资源在 webpack / VSIX 中的打包路径；现有项目使用单入口 `dist/extension.js`，不能假设独立 `node_modules` 会自动进入发行包。
- 试用样本与任务由谁提供；没有真实样本时先用夹具验证正确性，不宣称已经提升实际理解效率。
