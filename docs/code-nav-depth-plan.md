# 代码理解面板加深计划（D 阶段）

背景：M1–M3 交付后，面板能给出结构、入口和文件内静态关系，但摘要只有模板化一句话，作者写的注释完全没有进入结果，props 只有名字，关系只有 5 类，因此试用者反馈“分析太浅、没有注释、帮助不大”。

本计划只解决“看得更深”，不改动既有 5 类关系与跳转语义，也不引入任何网络调用。

## 边界

- 仍然**只做离线单文件**：只读当前编辑器的文本快照，不解析依赖、不读其他文件、不访问网络。
- 每条结论必须能定位到原文件行并可跳转；作者原文照抄，不翻译、不润色、不概括成模型语言。
- 静态无法确认的内容标注为“推定”或“未确认”，不能写成运行时事实。
- LLM 只作为可选增强，默认关闭，缺失时基础能力不受影响（本计划不实现）。

## 阶段

| 阶段 | 主要任务 | 通过条件 |
| --- | --- | --- |
| D1 注释与作者原话 | 采集 JSDoc / 行注释原文与 `@param`、`@returns`、`@deprecated` 等标签；采集模板注释；汇总 TODO / FIXME / HACK 清单；用作者注释改写首屏摘要并标注来源 | 函数、props、状态上的注释能显示并跳回原注释行；TODO 清单行号正确；摘要在有作者注释时引用原文并标注“作者原话”，无注释时回退到结构事实 |
| D2 组件契约与状态数据流 | props 的类型 / 必填 / 默认值 / validator；emits 声明与 `$emit` 触发点；slots、provide / inject、`v-model`；每个状态的读取者、模板绑定位置与 watch 依赖 | 面板能直接回答“这个组件的入参和出口是什么、谁改了这份状态、状态被模板哪里用到了”；凡是从语法推断的都带“推定”标记 |
| D3 顺序时间轴与修改影响面 | 初始化与生命周期顺序（标注“顺序推定”）；函数卡片补充签名、返回值、async、错误处理、被谁调用与改动波及面 | 面板能回答“改这个函数会影响哪些本文件位置”；顺序推定与实测结论在视觉上可区分 |

每个阶段完成前必须 `compile` + `lint` + 全量测试通过，再进入下一阶段。

## D1 交付细节

1. 协议新增 `doc`（脚本块顶部作者注释）、`comments`（TODO / FIXME / HACK / 备注，含模板注释）、`guide.summary.origin`（`comment` 表示引用作者原话，`structure` 表示结构事实），`NavNode.doc` 承载节点级注释。
2. 节点级注释只在**紧贴其上方**且独占整行的注释上生效；同一行的尾部注释不归属该节点，避免把上一行的说明算到下一个声明头上。
3. 摘要优先级：作者注释原文（截断到 80 字）> 组件名与入口数 > 导出数量。作者注释原文一律标记来源，不与结构事实混为一谈。
4. 面板首屏在入口卡片和结构区显示节点注释与 `@deprecated` 等标签；“待办与备注”在导读区显示前 8 条，完整结构区显示全部。
5. 不做的事：不翻译注释、不生成注释、不猜测注释含义、不因为注释存在就提高任何关系的确定性等级。

## D2 交付细节

1. 协议新增 `contract`：`props`（类型 / 必填 / 默认值 / validator / 写法来源）、`emits`（是否声明、声明行、本文件触发点）、`slots`（名称、行号、是否作用域插槽）、`injections`（provide / inject 键，静态无法确认时标 `unresolved`）、`flows`（每个状态 / prop / computed 的读取者、写入者、watch 与模板引用行）。
2. 宏解析覆盖 `<script setup>`：`defineProps` / `withDefaults` / `defineEmits` / `defineModel`，以及顶层 `provide` / `inject` / `watch`；Options API 覆盖 `props` 的对象与数组写法、`emits`、`model`、`provide` / `inject`、`computed` / `watch` / `methods` / `data`。
3. `defineProps<Props>()` 会按本文件内的 `interface` / `type` 做一次解引用；类型与默认值按源码原样保留（如 `[Number, String]` 写成 `Number | String`），不做语义推断。
4. 状态流转的“读取”跳过赋值左侧、更新表达式、声明 id、对象键与类型引用；`this.x` 参与读取判定，`this.x =` / `x.value =` / 裸 `x =` 记为写入。`v-for` / `v-slot` 引入的模板局部别名不算状态引用。
5. 面板在导读区新增“组件入参 / 对外事件 / 插槽 / 依赖注入”与“状态流转 · 谁读谁写”区块，所有条目可跳回源码；`revealLine` 只接受本次分析记录过的行，不开放任意行跳转。
6. 不做的事：不做跨文件依赖图、不推断运行时真实调用顺序（留给 D3）、不因为能从语法推断就把“推定”写成事实。

## D3 交付细节

1. 协议新增 `timeline`（初始化与生命周期步骤，`kind` 为 `state` / `computed` / `watch` / `hook`，引用 `nodes[].id`）与 `functions`（函数卡片）。
2. 时间轴按源码出现位置排序，面板明确标注“顺序推定”，不解释 `watch` 触发时机与异步先后。
3. 函数卡片补充 `signature`（`async? name(params)`）、`isAsync`、`hasReturn`（块体有无带值 `return`，箭头表达式体视为隐式返回）、`errorHandling`（是否出现 `try`）与 `params`。
4. 影响面复用 `paths` 中 `certainty: "certain"` 的 `calls` / `writes`：`callers`（谁调用它）、`callees`（它调用谁）、`writes`（它写了哪些状态）；跨文件或无法唯一解析的调用不进入卡片。
5. 面板在导读区新增“初始化与生命周期 · 顺序推定”和“函数卡片 · 签名与影响面”两个区块，条目可跳回源码；投影对时间轴与函数卡片各截断到 60 条并保留完整计数。
6. 不做的事：不做跨文件调用图、不推断运行时真实执行顺序、不把“顺序推定”渲染成确定的时序连线。
